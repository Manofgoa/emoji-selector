# Tray Icon

> Working document — the app lives in the notification area (tray): a smiley tray icon showing the
> last emoji used, a right-click menu to exit, and the window's close and minimize buttons hiding
> the window instead of ending the app.
> This file is the source of truth for the planned work until implemented,
> then the log of every adjustment made to it afterwards.

---

## Overview

Today the app is a skeleton: `Program.Main` parses `--title` and runs `MainForm`, an empty window.
Closing it ends the process.

This task makes the app a **resident** one, which the planned global shortcut needs:

- a **tray icon** is shown as long as the app runs, drawn at run time from an emoji;
- it starts as the default smiley and **follows the last emoji used** in the app, reset to the
  smiley at the next launch (never persisted);
- a **left click** on it shows or hides the window; a **right click** opens a menu to exit;
- the window's **close** (✕, Alt+F4) and **minimize** (_) buttons hide the window to the tray —
  the app keeps running.

Components touched: `Program.cs`, `UI/MainForm.cs`, a new tray-icon class under `UI/`, the docs.

## Tray Icon

| Point | Design |
|---|---|
| Visibility | Shown from start-up until the app exits, whether the window is shown or hidden |
| Default emoji | 😊 (`U+1F60A`), the one shown at every launch |
| Last emoji used | Each time an emoji is used in the app, the icon is redrawn with it. Not persisted: the next launch starts on the default again |
| Entry point | The tray icon exposes `ShowEmoji(string emoji)`; `MainForm` has **one** place calling it when an emoji is used. Nothing calls it yet — the picker is *Planned* — so that place carries a `//TODO:` saying the picker must call it |
| Drawing | Rendered at run time from the emoji's character sequence in **Segoe UI Emoji**, **in colour**, through **Direct2D + DirectWrite** (COM interop, colour fonts enabled) — no `.ico` file in the project, no third-party library. Size: the system small-icon size at the current DPI. The renderer is its own class, reusable later for the emoji grid |
| Tooltip | The window's title: `Emoji Selector`, or `Emoji Selector — <second title>` with `--title` — instances launched side by side are told apart in the tray too (truncated to the tooltip's limit if needed) |
| Lifetime | Disposed when the app exits, so no ghost icon stays in the tray; the icon handle of each drawn emoji is released when replaced |

The class owning it lives under `UI/` (working name `TrayIcon`), created and disposed by `MainForm`.

### Mouse

| Action | Effect |
|---|---|
| Left click (single) | Hidden window → shown, restored and brought to the foreground. Shown but behind other windows → brought to the foreground. Shown and already in front → hidden |
| Right click | Opens the context menu |

### Context Menu

| Item | Effect |
|---|---|
| `Exit` | Ends the app: tray icon removed, process ends |

No *Show* item: the left click does it.

## Window

| Event | Today | After |
|---|---|---|
| Close button ✕ / Alt+F4 (`CloseReason.UserClosing`) | Ends the app | **Hides** the window; the app keeps running in the tray |
| Minimize button _ | Taskbar | **Hides** the window to the tray; it comes back restored (not minimized) |
| Exit from the tray menu | — | Ends the app |
| Windows shutdown / logoff, Task Manager (`WindowsShutDown`, `TaskManagerClosing`…) | Ends the app | Ends the app — never blocked |
| Start-up | Window shown | Window shown (unchanged) |

- A hidden window has **no taskbar button** and is out of Alt+Tab; shown again, it keeps its last
  position and size.
- Only a user close is turned into a hide: any other close reason lets the app end.

## Design Iterations

Chronological log of design refinements, of the choices the implementation run
took on its own — flagged `🧭 Implementation choices` — and of every adjustment
requested afterwards — flagged `⚙️ Post-implementation`. One entry per request,
in the order the requests were made.

### Iteration 1 — 2026-10-07

Initial design from the request (tray icon with a smiley, right-click menu to exit, the window's
close button hiding to the tray) and the scoping answers:

- the icon is an emoji drawn at run time, **following the last emoji used**, reset to the default
  smiley at the next launch;
- a single left click toggles the window;
- the minimize button hides to the tray too; the app still starts with its window shown; the tray
  icon is always visible;
- no *Show* item in the menu.

Exploration (one direct pass, subject sized *straightforward*): the app is a skeleton with no
emoji picking and no test project, hence the first and third Open Questions.

### Iteration 2 — 2026-10-07

Every Open Question answered in one pass (Q&A 5–8):

- the last emoji used reaches the icon through an entry point only (`ShowEmoji`), not called until
  the picker exists;
- the emoji is drawn **in colour** through Direct2D + DirectWrite interop;
- no test project: checked by hand;
- the minor proposals are all accepted: `Exit` label, tooltip carrying the second title, a click
  on a window behind others brings it to front, *Tray icon* added to the glossary.

No unresolved question remains.

### Iteration 3 — 2026-10-07 — ✅ Implemented

Go given (Q&A 9): code, unit tests and documentation, in the current checkout, on `main` by the
user's choice (Q&A 10). Scope frozen on the design sections as of Iteration 2.
