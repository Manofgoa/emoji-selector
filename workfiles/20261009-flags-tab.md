# Flags Tab

> Working document — an eighth tab, **Flags**, holding Emojibase's whole `flags` group: the country
> and subdivision flags drawn from bundled **Twemoji** images (Segoe UI Emoji has none), the special
> flags drawn by Segoe as today's emojis are.
> This file is the source of truth for the planned work until implemented,
> then the log of every adjustment made to it afterwards.

---

## Overview

Segoe UI Emoji has **no flag glyphs**: a country flag shows as its two regional-indicator letters.
`Data/EmojiCatalog.cs` therefore leaves Emojibase's group 9 (`flags`) out, and the app has seven tabs
(RULES.md § Categories and Insertion; decided in
[20261007-category-tabs.md](20261007-category-tabs.md), Q&A 7, logged in `TODO-FEATURES.md`).

This workfile adds the **Flags** tab, last, with the whole group — 270 entries in the embedded
Emojibase 17.0.0 data. The emojis Segoe cannot draw come from **Twemoji** images bundled with the
app; the ones Segoe draws stay drawn by Segoe.

Agreed scope (step 5 scoping, Q&A 1–4):

| Point | Agreed |
|---|---|
| Image source | **Twemoji** — the maintained fork [jdecked/twemoji](https://github.com/jdecked/twemoji), graphics CC-BY 4.0 (attribution required), code MIT |
| Flags in the tab | **The whole Emojibase group**: country flags, the three subdivision flags (England, Scotland, Wales), the eight special flags — drawn by Segoe when it can |
| Where the images live | Embedded in the exe, **plus** a folder next to it holding the images a later Twemoji version changed or added — written by *Check for emoji updates…* (user request, Iteration 2) |

Fluent Emoji (MIT, the app icon) is **not** a candidate: it has no country flags — Microsoft ships
none, in the font or in the open-source set (secondary sources; not checked in the repository's
`assets` folder itself).

## What Segoe Draws

Checked on this machine (Windows 11, Segoe UI Emoji), by measuring and rendering each sequence:

| Flags | Count | Segoe draws | Source in the tab |
|---|---|---|---|
| 🏁 🚩 🎌 🏴 🏳️ | 5 | ✅ one glyph each | Segoe, as today's emojis |
| 🏳️‍🌈 🏳️‍⚧️ 🏴‍☠️ (ZWJ sequences) | 3 | ✅ one ligature each | Segoe |
| Country flags (regional-indicator pairs, `🇫🇷`) | ~258 | ❌ two letters | **Twemoji image** |
| England, Scotland, Wales (tag sequences on 🏴) | 3 | ❌ a bare 🏴, the tags ignored | **Twemoji image** |

- **The rule**: an emoji with a bundled image is drawn from it; any other through Segoe, as today.
  Only the images the tab needs are bundled — the country and subdivision flags, ~261 files — so the
  eight special flags keep Segoe's style, like every other emoji of the app.
- Consequence, accepted with the scope: the tab mixes two styles — Segoe's eight flags (Fluent, 3D)
  first in Emojibase's order, then Twemoji's flat country flags.

## Images

### Twemoji Facts

- Latest release found: **v17.0.3**, Emoji 17.0 — matches the embedded Emojibase 17.0.0.
- Formats: `assets/72x72/*.png` (72 × 72 only) and `assets/svg/*.svg` (a square 36 × 36 view box).
- File names: lowercase hex code points joined by `-`; `FE0F` dropped on a lone emoji, **kept inside
  ZWJ sequences** — none of the bundled files is one (countries and subdivisions have no `FE0F`), so
  the lookup is the emoji's code points, `FE0F` removed.
- Pinned download: `https://cdn.jsdelivr.net/gh/jdecked/twemoji@17.0.3/assets/svg/<name>.svg`.
- Estimated size of the subset (not measured): SVG ~100–150 KB, PNG 72 ~0.3–0.5 MB.
- Attribution: no fixed wording; the README accepts *"a mention in a project README or an 'About'
  section"*.

### Format and Sizes — to settle (*Open Questions* 1)

The app draws emojis at three sizes: the grid's cell (DPI-dependent), the details panel's 48 logical
pixels (96 px at 200 %), the tray icon's small-icon size (16–32 px).

| Option | Sharp at every size | Cost |
|---|---|---|
| **A. SVG, rendered by Direct2D** (recommended) | ✅ | Interop declared by hand: `ID2D1DeviceContext5` (`CreateSvgDocument`, `DrawSvgDocument`, Windows 10 1703+, below the app's 19041 target), queried from the renderer's WIC render target. Unsupported SVG features are silently ignored — Twemoji's flags are plain paths, to check on a render |
| B. PNG 72 × 72 | ❌ blurred above 72 px (the details panel at 200 %) | Decoding only (GDI+ `Bitmap`, then `DrawImage` into the renderer's `Format32bppPArgb` bitmap) |
| C. PNG 72 + PNG 144 rasterised at dev time | ✅ up to 144 px | A dev script rendering the SVGs (Edge headless, like `New-AppIcon.ps1`), twice the files |

Twemoji's canvas is **square**: the image fills the emoji's square bitmap as a glyph does, no aspect
fitting (unlike the details panel's rectangular `UI/Flags/` images).

### Where They Live — Embedded, Plus an Update Folder

Two layers, looked up in this order (`FlagImages`):

| Layer | Holds | Written by |
|---|---|---|
| 1. **`flag-images\` next to the exe** (kebab-case, `FlagImages.FolderName`) | Only the images a **newer** Twemoji version **changed or added**, with that version's `version.txt` and `LICENSE-GRAPHICS` | *Check for emoji updates…* (see *Flag Images Update* below) |
| 2. **Embedded in the exe**, like `UI/Flags/` and the Emojibase copy | Every image the tab needs at the exe's Twemoji version | The dev script, at build time |

- Unlike `emoji-data\`, the folder is **never** written from the embedded copy: it holds the
  difference only, and is missing until an update writes it.
- **At launch** (`FlagImages.Load`):

  | The folder | Does |
  |---|---|
  | Missing | Embedded images only |
  | `version.txt` missing or not a version | Ignored — embedded images only |
  | Version **not newer** than the embedded one (the exe was updated since) | Ignored — the embedded copy is at least as recent — and deleted when it can be |
  | Newer | Its images first, the embedded ones for the rest |
  | One of its images unreadable, or failing to draw | That image skipped, the embedded one used — never an error |

- `Reset all settings…` deletes the folder: a new row in `AppReset`, from `FlagImages.FolderName`
  (RULES.md § Reset All Settings).

### Getting Them into the Repository

- A dev script, e.g. `src/EmojiSelector/Flags/Update-FlagImages.ps1`, modelled on `New-AppIcon.ps1`:
  reads group 9 of `Data/Emojibase/compact.en.json`, leaves out the eight Segoe draws, downloads each
  file from jsDelivr at a **pinned** Twemoji version, writes them with Twemoji's `LICENSE-GRAPHICS`
  and a `version.txt`. The files are **committed**; the build downloads nothing.
- Embedded with a wildcard `EmbeddedResource` and a `LogicalName`, `WithCulture="false"` — as
  `UI/Flags/` and the Emojibase files.

### Flag Images Update

*Check for emoji updates…* (`MainForm.CheckEmojiUpdatesAsync`, `Data/EmojiDataUpdate.cs`) checks the
flag images too, on the same click — still the app's only network access, still no check at launch.

- **The list to cover**: the flags of the emoji list **in use after the update** — the newly
  downloaded Emojibase data when it is updated in the same run — that Segoe does not draw (see *What
  Segoe Draws*): a new flag brought by Emojibase gets its image in the same pass when Twemoji has it.
- **Latest version** — to settle (*Open Questions* 9): proposed, jsDelivr's data API,
  `https://data.jsdelivr.com/v1/packages/gh/jdecked/twemoji/resolved?specifier=latest` (the same CDN
  as the Emojibase download; no GitHub API rate limit). Not newer than the version in use (the
  folder's, else the embedded one) → nothing to do for the flags.
- **What changed** — to settle (*Open Questions* 10): proposed, jsDelivr's flat file listing of that
  version, `https://data.jsdelivr.com/v1/packages/gh/jdecked/twemoji@<version>?structure=flat`, which
  gives each file's hash: a file of the list whose hash differs from the embedded one, or that the
  exe does not have, is downloaded; the others are not. A file the listing does not have keeps its
  current image (or Segoe).
- **Written as a set**: the downloaded images, `LICENSE-GRAPHICS` and `version.txt` (last) into a new
  folder `flag-images.new\` then swapped for `flag-images\` — never half a version. Nothing changed
  (every hash equal) → only `version.txt` and the licence written, so the check answers *up to date*
  next time.
- **The dialogs** — to settle (*Open Questions* 11): proposed, **one** question for both sources,
  naming what is newer (`Emoji list 17.0.0 → 18.0.0`, `Flag images 17.0.3 → 17.0.4`), Yes / No, *Yes*
  the default; each source downloaded and written on its own — a failure of one is reported (`Could
  not update the flag images`, a warning) and does not undo the other; then the same `Restart now to
  use it?`.
- `--background` restarts, the single instance and the rest of the existing flow are unchanged.

### Attribution — to settle (*Open Questions* 3)

## Rendering

### One Seam: `EmojiRenderer.Render`

`EmojiRenderer.Render(string emoji, int size)` (`Drawing/EmojiRenderer.cs:47`) is the only function
turning an emoji into a bitmap, and has **three callers**:

| Caller | Where | Size |
|---|---|---|
| Grid pre-render | `Drawing/EmojiBitmapCache.cs:177`, background thread | The cell's emoji size |
| Details panel | `UI/EmojiDetailsPanel.cs:559` | 48 logical px |
| Tray icon | `UI/TrayIcon.cs:58` | `SystemInformation.SmallIconSize` |

- The branch goes **at the top of `Render`**: an emoji with a bundled image is drawn from it, into the
  same square transparent `Format32bppPArgb` bitmap. The three callers get the flags without a change
  of their own — the grid, the details panel's large view and `Use as tray icon` alike.
- A new class owns the images (e.g. `Drawing/FlagImages.cs`): text → file name (code points, `FE0F`
  removed) → embedded resource; thread-safe, read-only — each thread's renderer draws on its own.
- A failure loading or drawing an image → the emoji is drawn through Segoe (two letters), never an
  error; the pre-render's `catch` (`EmojiBitmapCache.cs:179`) covers the new exception types.

### Disk Cache Key — to settle (*Open Questions* 4)

`EmojiBitmapCache.BuildKey` (`:227-240`) holds `FormatVersion` (1), the size, Segoe UI Emoji's file,
a hash of the emoji list, the renderer's scales.

- Adding the tab changes the emoji list: the key changes by itself, no bump needed for that.
- But a new set of images (a Twemoji update with the same emoji list — an exe carrying newer images,
  or an update writing `flag-images\`) would not be seen: proposed, a key component
  **`flags=<Twemoji version in use>`** — the folder's `version.txt` when it is used, else the embedded
  one — rather than a `FormatVersion` bump at each image update.
- `FormatVersion` is bumped only if the atlas or the compositing changes — it does not here.

## Catalog and Tab

- `Data/EmojiCatalog.cs`: a `Flags = 9` constant and an eighth `Tabs` row, **last** — Emojibase's
  order, after Symbols. The remark saying flags are left out goes.
- **Name** `Flags`; **glyph** — to settle (*Open Questions* 5): proposed Segoe Fluent Icons `E7C1`
  (*Flag*), present in Segoe MDL2 Assets too (the Windows 10 fallback).
- The window's minimum width follows the tab count by itself (`CategoryTabStrip.LogicalMinimumWidth`,
  44 logical px per tab); the default width (16 columns) is wider than eight tabs.
- **A flag without an image** — a new one brought by `Check for emoji updates…` that Twemoji does not
  have yet (the update downloads its image when it has one, see *Flag Images Update*): to settle
  (*Open Questions* 6); proposed, kept and drawn by Segoe (two letters), as RULES.md keeps an emoji
  newer than the system font (a box).

### Everything Else Unchanged

A flag is an emoji like any other once it has a bitmap — to confirm (*Open Questions* 7):

| Feature | Behaviour |
|---|---|
| Insertion, copy button | The emoji's **text** — regional indicators, tag sequence — whatever the target app draws |
| Search | Emojibase's names and tags in English and French: `flag: France` / `drapeau : France`, tag `FR`; `drapeau : Angleterre`. No change to `EmojiSearch` |
| Details panel | The image at 48 logical px; names, tags, `U+1F1EB` as the copy button's tooltip |
| Frequent tab, custom groups | Keyed by the text: a flag is counted, added to a group, reordered as any emoji; their sections reuse the grid's bitmaps |
| `Use as tray icon` | The flag shown in the notification area (drawn through the same `Render`) |
